# 同步恢复与故障排查

## 中断与残留锁

中断后直接重跑 `hust-mail-cli sync`，已完成的邮件会自动跳过，无需额外修复命令。

```sh
# SSH 后台长期同步
nohup hust-mail-cli sync > ~/hust-mail-sync.log 2>&1 < /dev/null &
```

同步使用系统 `flock` 独占锁，即使进程被 `kill -9` 结束，内核也会释放它。新版残留的 PID 标记会在下一次同步时自动回收。旧版纯 PID 锁只有在确认原进程不存在时才会回收；PID 仍存活、无权检查或标记无法识别时，工具拒绝自动删除，防止误抢正在使用的归档。

`.sync.flock` 是长期保留的内核锁文件，存在本身是正常现象，**不要手工删除它**。异常退出留下的 `.download-*`、`.lock-*` 临时文件不会阻止重跑；如需清理，应在确认该账号没有同步进程运行后操作，保留 `.eml` 邮件。

程序处理 `SIGHUP`、`SIGINT` 和 `SIGTERM`，收到信号后取消操作并清理锁。SSH 断开可能终止裸 `&` 后台任务；这不代表任务会持续运行，但重跑不会因新版残留锁而被永久阻塞。希望断开连接后继续同步，请使用 `nohup` 或 `tmux`。锁机制面向 Linux/macOS 本地文件系统；不支持锁的文件系统会明确报错。

## 登录或配置失败

- 确认 `user` 是完整邮箱地址，`password` 是[网页端生成的客户端专用密码](client-password.md)，不是专用密码名称或网页登录密码。
- 配置含密码时，执行 `chmod 600 ~/.config/hust-mail-cli/config.json`，限制其他用户读取。
- 使用 `hust-mail-cli folders` 检查只读 IMAP 连接；确认主机、端口及专用密码对应的协议访问权限。
- 总操作超时可使用 `--timeout 60m` 调整；终端输入密码的时间不计入该限制。

## 邮件仍存在但服务器不返回正文

如果正文请求返回成功状态却没有正文，CLI 会再次查询该 UID 的元数据。错误会说明邮件是否仍存在；能读取大小时会显示 `RFC822.SIZE`，不会直接认定邮件已删除。

这类单封邮件内容缺失默认忽略，警告会列出文件夹及 UID，后续邮件和其他文件夹继续同步。末尾显示 `Complete` 和 `ignored` 数量，正常退出；不会为忽略的邮件保存空文件，也不会把它计入下载数量。连接、身份校验和本地写入失败仍立即报错。

确认邮件仍存在但正文不可读时，会在对应文件夹的 UIDVALIDITY 目录下保存 `.ignored-<UID>.json`，权限为 `0600`。记录按账号、文件夹、UIDVALIDITY 和 UID 隔离，不包含邮件正文或凭据。后续同步直接跳过这些 UID，不再请求正文或重复打印逐封警告；汇总中的 `ignored` 仍会显示跳过数量。搜索后邮件已消失、连接失败或协议错误不会写入此记录。

需要全量同步时使用 `hust-mail-cli sync --days 0`。如果服务端问题已解决，可用以下命令主动重试已忽略的邮件：

```sh
hust-mail-cli sync --retry-ignored --days 0
```

重试成功后清除该邮件的忽略记录；仍无法读取时保留记录并告警。已有完整 `.eml` 优先视为已下载，忽略记录本身不会冒充邮件文件。新版本第一次遇到此前只在日志中出现过的错误时，仍需告警一次并建立记录。

如果相同 UID 持续失败，请在网页端检查该邮件是否能完整打开或下载，必要时向邮箱服务支持反馈 UID 和大小。服务器暂不提供正文时，该邮件不会归档；`ignored` 不代表这些邮件已备份。请将忽略记录与归档一起保留，删除后下次同步会重新尝试。

## 旧连接配置迁移

CLI 固定使用只读 IMAP 收信和 SMTP 发信，不再支持 POP3 或连接覆盖。旧配置需删除 `protocol`、`host`、`port`、`smtp`，命令行也需移除 `--protocol`、`--host`、`--port`。收到 `removed config fields` 时，请按提示删除对应字段，参见[迁移说明](configuration.md#旧配置迁移)。已有 `.eml` 仍可读取；`list`、`search` 使用的配置也需完成迁移，或通过 `--config` 指定精简配置。`read` 和附件操作不读取账号配置。迁移不删除旧归档。

## 正文无法解码或超过限制

缺失媒体类型的 MIME 段会采用默认值，具备文件名或附件 disposition 的段仍按附件处理。未知正文 charset 会回退 UTF-8，不再仅因此跳过整封邮件；无效 UTF-8 字节显示为替换符，原始 `.eml` 保持不变。

`read` 和 `search` 对解码后正文有 8 MiB 限制。需要查看原始内容时使用 `hust-mail-cli read --raw /path/to/message.eml`。附件导出不需要将附件内容转换为正文。

## 搜索第一次运行很慢

首次正文搜索需要扫描原始邮件、解码并写入本地缓存，不能用重复查询的耗时估算它。长任务默认每 5 秒在 stderr 输出扫描、匹配、跳过、缓存命中数量及已用时间；`--quiet` 会关闭进度。不要将单次无输出直接认定为卡死。

解码规则升级后旧版本缓存自动失效，首次查询需按需重建。`--rebuild-index` 用于显式清理重建，`--no-index` 完全绕开缓存；两者不能同时使用。缓存是派生数据，损坏可重建，不修改原始邮件。
